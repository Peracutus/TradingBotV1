# TradingBotV1

Исследовательский framework для BTC/ETH spot: детерминированный replay, виртуальные счета, общий контроль риска и журнал SQLite.

**Статус:** исходники release candidate V1.0.1. Локальное paper-испытание продолжается. Техническая приёмка и статистическая валидация стратегий — отдельные этапы. Реальные ордера в этой реализации отсутствуют.

## Что внутри

- `trading_v1/` — одно ядро исполнения и Decimal-учёта для replay и paper, идемпотентность, защитные состояния, SQLite и локальная read-only панель.
- `research_v0/`, `research_framework.py` — исходные реализации исследовательских стратегий.
- `hypotheses_50.json` — каталог гипотез; наличие идеи не означает допуск к торговле.
- `tests/` — технические и регрессионные проверки ядра.
- `docs/v1/CONTRACT.md` — формулы, причинность, риск и восстановление.
- `cross_market/` — независимый архивный исследовательский reference; Apex не допущен к общему paper-портфелю.

## Локальная установка

Python 3.13, виртуальная среда:

```sh
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-v1.txt
```

Ядро можно попробовать без сети, ключей и исторических архивов:

```sh
python examples/replay_demo.py
```

Это синтетическая демонстрация учёта, не бэктест реального рынка.

Технические проверки:

```sh
python -m unittest discover -s tests -p test_trading_v1.py -v
```

Один тест использует локальный loopback-порт. Полный регрессионный набор `test_v1_bugfix.py` также содержит сценарий запуска paper, которому необходим локальный исторический bundle.

## Данные и полный replay/paper

В публичном репозитории нет локальных свечных архивов, замороженных исследовательских результатов, исходных журналов paper и настроек пользователя. Команды `python -m trading_v1 replay`, `paper`, `recorded` и `controls` сохраняют исходный контракт проекта и требуют соответствующих локальных входных файлов.

Для стандартного paper требуются локальные BTC/ETH 4h CSV в `five_year_validation/data/{BTCUSDT,ETHUSDT}/`, доступ к публичным REST/WS Bybit и исходный baseline bundle `baselines/2026-10-07_ema30_100_200_stop2/`. Для архивного replay дополнительно нужны минутные архивы и provenance manifests в `external_benchmarks/observed_1m/`. Проверку baseline нельзя обходить или подменять фиктивным результатом. Без этих входов используйте синтетическую демонстрацию и unit-тесты.

Рыночные архивы и исходные результаты должны загружаться и храниться локально. Секреты, реальные счета и базы исполнения не коммитятся. Панель привязана к `127.0.0.1`; публичного управления торговлей нет.

## Ограничения

Минутный OHLCV не восстанавливает tick-путь, стакан или гарантированное исполнение. Комиссии и проскальзывание моделируются. R1 означает технический допуск, а не доказанную прибыльность. Подбор правил и OOS-проверка должны выполняться отдельно. Автоматического повышения допуска и подбора весов нет.

Публикация исходников не меняет и не перезапускает локальный paper-эксперимент.
